---
title: Delivery and retries
description: Status handling, durable retries, endpoint disabling, and destination security
---

Spectrum delivers each event independently to every subscribed endpoint. A
slow endpoint cannot block another endpoint, and retries for a failing endpoint
run in its own ordered lane.

## Delivery contract

- Delivery is **at least once**. Deduplicate with `webhook-id`.
- Order is preserved for one project, platform, and endpoint.
- A normal asynchronous attempt has a 20-second response timeout.
- Any `2xx` response acknowledges the event.
- Redirects are never followed.
- Retryable failures are retained for up to four days from the first failure.
- Spectrum honors a valid `Retry-After` value without extending the four-day
  budget.

Return `2xx` after verifying the signature and durably enqueueing the event.
Run slow application work after acknowledgement.

```ts
app.post("/spectrum-webhook", async (request) => {
  const verified = await verifyWebhook(request);
  if (!verified) return new Response("invalid signature", { status: 401 });

  await durableQueue.send(verified.event);
  return new Response("ok", { status: 200 });
});
```

## Status-code behavior

| Response | Result |
| --- | --- |
| `2xx` | Delivered; no further attempts. |
| `3xx` | Terminal failure. Spectrum does not follow redirects. |
| `404`, `408`, `429` | Retryable. |
| `410 Gone` | The endpoint is disabled immediately with reason `receiver_gone`. |
| Other `4xx` | Terminal failure because another attempt is unlikely to help. |
| `5xx` | Retryable. |
| Network, DNS, or timeout failure | Retryable when the destination remains a valid public HTTPS target. |

For `429`, `502`, and `504`, Spectrum applies a minimum delay before trying
again. A valid `Retry-After` delay or HTTP date takes precedence when it is
later than the scheduled attempt.

<Warning>
Only return `410` when you want Spectrum to stop sending to this endpoint. A
temporary outage should return `503` or `429`.
</Warning>

## Retry schedule

Transient failures first use short broker retries. If the endpoint continues to
fail, Spectrum moves the endpoint into a durable FIFO retry lane. Delays grow
from seconds to minutes and then hours, with jitter to avoid synchronized retry
spikes. The final deadline is four days after the first failed attempt.

Fresh events for that endpoint stay behind the failed head while it is in the
retry lane. This preserves endpoint order without holding up healthy endpoints.
When the endpoint recovers, the queue drains in order and rejoins the primary
delivery lane.

If the four-day retry budget expires, Spectrum:

1. moves the event to its internal dead-letter queue;
2. disables the endpoint with reason `delivery_failures`; and
3. sends an email if `failureNotificationEmail` is configured.

Re-enable the endpoint with `PATCH /projects/{projectId}/webhooks/{webhookId}`
and `{ "enabled": true }` after fixing it. Future events and any retries that
are still pending resume in endpoint order. Spectrum does not currently expose
delivery history or manual replay, so reconcile terminal failures from your own
source of truth.

## Destination security

Spectrum validates the destination before connecting:

- HTTPS is required.
- Every resolved address must be public. Loopback, private, link-local,
  carrier-grade NAT, unique-local IPv6, and cloud-metadata addresses are
  blocked.
- The validated address is pinned through the TLS connection to prevent DNS
  rebinding.
- Redirects are rejected, including HTTP-to-HTTPS and trailing-slash redirects.

Register the final public URL directly. Destination checks also run at delivery
time so a later DNS change cannot route requests into a private network.

## Static egress addresses

Production webhook traffic currently leaves from:

- `52.9.146.229`
- `52.52.141.21`

Allowlist every address. Retrieve the environment's authoritative set at
runtime rather than hard-coding the list indefinitely:

```sh
curl "https://spectrum.photon.codes/projects/$PROJECT_ID/webhooks/egress-ips" \
  -u "$PROJECT_ID:$PROJECT_SECRET"
```

The response is `{ "succeed": true, "data": { "addresses": [...] } }`.
Spectrum will publish changes before moving delivery traffic to a new address.
