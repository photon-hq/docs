---
title: Verifying signatures
description: Verify Standard Webhooks signatures against the exact request bytes
---

Verify every delivery before parsing or processing it. Spectrum signs the exact
UTF-8 JSON bytes sent on the wire and provides the Standard Webhooks fields in
three headers:

| Header | Value |
| --- | --- |
| `webhook-id` | Stable event id. |
| `webhook-timestamp` | UNIX epoch seconds at signing time. |
| `webhook-signature` | One or more space-delimited `v1,<base64>` values. |

HTTP header names are case-insensitive. Many frameworks expose these names in
lowercase.

## Signature construction

Remove the `whsec_` prefix from the endpoint's Standard secret and Base64-decode
the remainder. Then calculate:

```text
signed-content = webhook-id + "." + webhook-timestamp + "." + exact-body-bytes
signature      = Base64(HMAC-SHA256(decoded-secret, signed-content))
header-value   = "v1," + signature
```

During secret rotation, the header contains signatures for both the current and
still-valid previous secret:

```text
webhook-signature: v1,NEW_SIGNATURE v1,OLD_SIGNATURE
```

Accept the request if any `v1` value matches the secret currently deployed to
your service.

## Node and Bun

```ts
import { createHmac, timingSafeEqual } from "node:crypto";

type StandardHeaders = {
  "webhook-id": string;
  "webhook-timestamp": string;
  "webhook-signature": string;
};

export function verifySpectrumWebhook(
  body: Uint8Array,
  headers: StandardHeaders,
  serializedSecret: string,
  nowSeconds = Math.floor(Date.now() / 1000),
): boolean {
  const timestamp = Number(headers["webhook-timestamp"]);
  if (!Number.isInteger(timestamp)) return false;
  if (Math.abs(nowSeconds - timestamp) > 5 * 60) return false;

  const encodedSecret = serializedSecret.replace(/^whsec_/, "");
  const key = Buffer.from(encodedSecret, "base64");
  const expected = createHmac("sha256", key)
    .update(`${headers["webhook-id"]}.${headers["webhook-timestamp"]}.`)
    .update(body)
    .digest();

  return headers["webhook-signature"].split(" ").some((entry) => {
    const [version, encodedDigest] = entry.split(",", 2);
    if (version !== "v1" || !encodedDigest) return false;

    const actual = Buffer.from(encodedDigest, "base64");
    return actual.length === expected.length && timingSafeEqual(actual, expected);
  });
}
```

Read the body as bytes exactly once:

```ts
const body = new Uint8Array(await request.arrayBuffer());

if (!verifySpectrumWebhook(body, headers, process.env.WEBHOOK_SECRET!)) {
  return new Response("invalid signature", { status: 401 });
}

const event = JSON.parse(new TextDecoder().decode(body));
```

The same wire format works with Standard Webhooks consumer libraries. Pass the
full `whsec_` value and the raw request body according to the library's API.

<Warning>
Middleware that parses JSON before your handler can destroy the signed byte
sequence. Configure a raw-body route, or retain the framework's original body
buffer for verification.
</Warning>

## Replay protection and idempotency

A correct HMAC proves authenticity and integrity, but an attacker could resend
a captured request. Apply both controls:

1. reject a `webhook-timestamp` outside a small clock-skew window, such as five
   minutes; and
2. insert `webhook-id` into a store with a unique constraint before performing
   non-idempotent work.

## Rotation without downtime

Call the [rotation endpoint](/webhooks/managing-webhooks#rotate-the-standard-secret)
with an overlap window. Old deployments continue matching the old signature in
the multi-signature header while new deployments match the new one. After every
instance uses the new secret and `previousValidUntil` has passed, remove the old
secret.

If a secret is exposed, rotate with `{ "overlapSeconds": 0 }` and deploy the
new value immediately.

## Legacy Spectrum signature

Existing integrations can continue verifying `X-Spectrum-Signature` with the
legacy `signingSecret`:

```text
X-Spectrum-Signature = "v0=" + Hex(HMAC-SHA256(
  legacy-secret,
  "v0:" + X-Spectrum-Timestamp + ":" + exact-body
))
```

The Standard and legacy headers are additive and sign the same body. New
integrations should use the Standard headers so rotation and compatible
consumer libraries work without custom protocol code.
